## Abstract

This proposal extends `helm dependency update` and `helm dependency build` to support charts stored in OCI registries without requiring prior extraction to the local filesystem. Currently these commands only work on unpacked local charts. This enhancement enables workflows where charts remain packaged in OCI registries while still supporting plugin and subchart dependency resolution.

## Motivation

With the introduction of chart-defined plugins in Charts v3, users have a new dependency type that doesn't require modification of the chart directory itself. Unlike subcharts, which must be extracted to the chart's `charts/` subdirectory, plugins are downloaded to a user-level content cache. This architectural difference opens the possibility of running dependency commands on charts that haven't been extracted locally.

### Current Limitations

1. **Local extraction required**: `helm dependency update` and `helm dependency build` fail with "only unpacked charts can be updated" when given anything other than a local directory path.

2. **OCI workflow friction**: Users working with OCI-stored charts must:

   ```bash
   helm pull oci://registry/charts/myapp:1.0.0 --untar
   cd myapp
   helm dependency update
   # Now work with the extracted chart
   ```

3. **Plugin-only charts**: Charts v3 charts that only define plugins (no subcharts) still require local extraction despite plugins being cached externally.

### Use Cases

1. **Plugin pre-caching**: Download all plugins referenced by an OCI chart without extracting the chart itself:

   ```bash
   helm dependency update oci://registry/charts/myapp:1.0.0
   ```

2. **CI/CD pipelines**: Validate that all dependencies are resolvable before deployment without extracting charts.

3. **GitOps workflows**: Tools like Flux can resolve chart dependencies during reconciliation without requiring local chart extraction.

## Rationale

### Why Extend Existing Commands?

Rather than creating new commands, extending `helm dependency update/build` provides:

1. **Consistency**: Same mental model for all chart sources
2. **Tool compatibility**: Existing scripts and CI/CD pipelines work with minimal changes
3. **Discoverability**: Users don't need to learn new commands

### Why Charts v3 Only?

1. **Plugin support**: Only Charts v3 supports chart-defined plugins, which are the primary motivator for this feature
2. **Clean boundary**: Breaking changes are isolated to charts that explicitly opt in
3. **Consistency**: Follows the pattern established by HIP-0020 for new chart features

### Architectural Considerations

The dependency resolution for OCI charts works differently based on dependency type:

| Dependency Type | Current Behavior          | OCI Chart Behavior               |
| --------------- | ------------------------- | -------------------------------- |
| Subcharts       | Extract to `charts/`      | Require local extraction (error) |
| Plugins         | Download to content cache | Download to content cache        |

This asymmetry is intentional: subcharts must be bundled with the chart for installation, while plugins are resolved at runtime from the cache.

## Specification

### Command Extension

Both `helm dependency update` and `helm dependency build` will accept OCI URIs:

```bash
helm dependency update oci://registry/charts/myapp:1.0.0
helm dependency build oci://registry/charts/myapp:1.0.0
```

### Behavior for OCI Charts

#### Plugin-Only Charts

For Charts v3 with only plugin dependencies (no subcharts):

1. Download chart metadata (Chart.yaml, Chart.lock) from OCI registry
2. Parse plugin dependencies
3. Download plugins to content cache
4. Success

```bash
$ helm dependency update oci://registry/charts/plugin-only-chart:1.0.0
Downloading 2 plugins
Downloaded: gotemplate-render@0.1.0
Downloaded: varsubst-render@0.1.0
```

#### Charts with Subcharts

For Charts v3 with subchart dependencies:

1. Download chart metadata from OCI registry
2. Check for Chart.lock
3. If Chart.lock exists and subcharts are present in the package, download plugins only
4. If Chart.lock missing or subcharts not present, error with guidance:

```bash
$ helm dependency update oci://registry/charts/has-subcharts:1.0.0
Error: chart has subchart dependencies that require local extraction.
Run: helm pull oci://registry/charts/has-subcharts:1.0.0 --untar
Then: helm dependency update ./has-subcharts
```

This error is intentional: subchart resolution requires writing to the chart's `charts/` directory, which is impossible for a remote OCI chart.

### Lock File Handling

For OCI charts:

1. **Reading**: Lock files are read from the OCI chart package
2. **Writing**: Lock file updates are not supported (chart is read-only)

If the lock file is missing or outdated, the command fails with guidance to extract and update locally:

```bash
$ helm dependency update oci://registry/charts/myapp:1.0.0
Error: Chart.lock is missing or outdated. Extract the chart to update dependencies:
  helm pull oci://registry/charts/myapp:1.0.0 --untar
  helm dependency update ./myapp
  helm push myapp-1.0.1.tgz oci://registry/charts
```

### New Flags

| Flag             | Description                                                |
| ---------------- | ---------------------------------------------------------- |
| `--plugins-only` | Only resolve plugin dependencies, skip subchart validation |
| `--dry-run`      | Show what would be downloaded without downloading          |

Example:

```bash
# Download plugins for an OCI chart without checking subcharts
helm dependency update --plugins-only oci://registry/charts/myapp:1.0.0

# Preview dependency resolution
helm dependency update --dry-run oci://registry/charts/myapp:1.0.0
```

### Error Messages

Clear error messages for unsupported operations:

```
Error: cannot update Chart.lock for OCI chart (read-only)
Hint: Extract the chart locally to update the lock file

Error: subchart 'mysql' is not present in chart package
Hint: Chart was packaged without dependencies. Extract and run 'helm dependency update' locally

Error: plugin 'custom-render' requires OCI registry authentication
Hint: Run 'helm registry login registry.example.com' first
```

## Backwards Compatibility

### Existing Behavior Preserved

- Local directory paths work exactly as before
- Charts v2 continue to work unchanged
- No changes to lock file format

### New Functionality

- OCI URIs as arguments (new, additive)
- `--plugins-only` flag (new, additive)
- `--dry-run` flag (new, additive)

## Security Implications

### OCI Registry Authentication

Plugin and chart downloads from OCI registries use existing Helm registry authentication. No new authentication mechanisms are introduced.

### Content Trust

When pulling chart metadata from OCI, the same verification mechanisms apply as for `helm pull`:

1. Digest verification (always)
2. Signature verification (when `--verify` specified)

### Plugin Trust

Plugins downloaded from OCI are subject to the same trust model as subchart dependencies:

1. Repository specified in Chart.yaml
2. Version pinned in Chart.lock (when present)
3. Digest verified (when available)

## Reference Implementation

Implementation touches the following packages:

1. **`pkg/cmd/dependency_update.go`**: Accept OCI URIs, dispatch to appropriate handler
2. **`pkg/cmd/dependency_build.go`**: Accept OCI URIs, dispatch to appropriate handler
3. **`pkg/downloader/manager.go`**: Add OCI chart handling methods
4. **`pkg/downloader/oci.go`** (new): OCI-specific metadata extraction and dependency resolution

Key implementation details:

```go
// Detect OCI URI and handle appropriately
func (m *Manager) Update() error {
    if registry.IsOCI(m.ChartPath) {
        return m.updateOCI()
    }
    // ... existing local path logic
}

// OCI-specific update: read-only, plugins only
func (m *Manager) updateOCI() error {
    // 1. Pull chart metadata from OCI
    meta, lock, err := m.pullOCIMetadata(m.ChartPath)
    if err != nil {
        return err
    }

    // 2. Check for subchart dependencies
    if len(meta.Dependencies) > 0 && !m.PluginsOnly {
        return fmt.Errorf("chart has subchart dependencies that require local extraction")
    }

    // 3. Download plugins to content cache
    if len(meta.Plugins) > 0 {
        return m.downloadPlugins(meta.Plugins)
    }

    return nil
}
```

## Rejected Ideas

### Automatic Chart Extraction

Rejected: Automatically extracting OCI charts to a temp directory would hide complexity and create cleanup issues. Explicit local extraction gives users control.

### Lock File Updates for OCI Charts

Rejected: OCI charts are immutable once pushed. Modifying lock files would require re-pushing, which changes the version and digest. Users should update locally and push new versions.

### Support for All Chart Versions

Rejected: Charts v2 don't support plugins, so the primary motivation doesn't apply. Keeping this feature v3-only maintains consistency with the plugin feature.

## Open Issues

### Registry API Requirements

Should Helm require specific OCI registry capabilities (e.g., ability to fetch individual layers vs. full pull)?

**Current answer**: Use existing `helm pull` mechanisms to fetch the complete chart, then extract metadata. This is less efficient but more compatible.

### Subchart Pre-validation

Should `helm dependency update` for OCI charts validate that declared subcharts exist in the package?

**Current answer**: Yes, to provide early feedback. But this adds overhead—may need `--skip-subchart-validation` flag.
